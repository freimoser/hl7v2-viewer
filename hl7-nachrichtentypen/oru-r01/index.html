HL7 ORU^R01: Laborbefund-Nachricht mit Beispiel

ORU^R01 überträgt Beobachtungsergebnisse, zum Beispiel Laborbefunde, vom ausführenden System an den Empfänger, ohne dass dafür eine eigene Abfrage nötig ist. OBR beschreibt die Untersuchung, jedes OBX liefert einen Einzelwert.

Worauf Sie achten sollten

  • Gruppierung: Jedes OBX gehört zum davor stehenden OBR. Beginnt ein neues OBR, beginnt eine neue Untersuchung. Ein NTE gehört zum Segment direkt davor, im Beispiel zum letzten OBX.
  • OBX-2 Werttyp: Er bestimmt, wie OBX-5 zu lesen ist. Im Beispiel NM (Zahl) und ST (Text). Weitere Typen sind unter anderem TX (Freitext), CWE (codiert) und ED (eingebettetes Dokument).
  • OBX-3 Beobachtungskennung: Code ^ Text ^ Codesystem. Im Beispiel ein lokales System (LOKAL). In der Praxis steht dort oft LN für LOINC. Ein lokaler Code ist nur im Absendersystem verständlich.
  • Zahlen: Bei NM steht ein Dezimalpunkt (5.9), kein Komma. Einheit in OBX-6, Referenzbereich in OBX-7. Der Viewer warnt bei 5,9.
  • OBX-8 Kennzeichen: N normal, H hoch, L niedrig, A auffällig. Im Beispiel ist Kalium als H markiert. Der Viewer wertet das nicht medizinisch.
  • Status: OBX-11 und OBR-25 tragen den Ergebnisstatus: F endgültig, P vorläufig, C korrigiert, X nicht durchführbar. Ein Korrekturbefund (C) ersetzt einen früheren Wert.
  • Auftragsnummern: ORC-2/OBR-2 sind die Auftragsnummer des Anfordernden (PL-5501), ORC-3/OBR-3 die des Ausführenden (FL-9901). Damit ordnet der Empfänger den Befund dem Auftrag zu.
  • Freitext: \.br\ im NTE ist ein Zeilenumbruch. Eingebettete Dokumente (Typ ED) stehen oft als lange Base64-Zeichenkette in OBX-5, der Viewer zeigt sie als Text.
  • Befunde im deutschen LDT-Format liest der LDT-/BDT-Viewer.
